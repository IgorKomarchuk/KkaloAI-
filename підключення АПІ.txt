Згідно з вашим SnapCal_Business_Plan.docx (Розділ 4 "Технічний стек" та Розділ 8 "Таблиця витрат"), для повноцінної роботи додатка потрібно налаштувати 5 ключових сервісів та API.

Ось їхній перелік та що саме потрібно зробити (або перевірити, чи вже зроблено):

1. Google Gemini API (Штучний інтелект для розпізнавання їжі)
Для чого: Це "мозок" додатку (Gemini 2.5 Flash), який перетворює фото на калорії за 2 секунди.
Що потрібно від вас:
Зайти в Google AI Studio (або Google Cloud Console).
Згенерувати Gemini API Key.
Цей ключ потрібно вставити у файл local.properties (у корені вашого Android проекту) у такому форматі: GEMINI_API_KEY=ваш_довгий_ключ_тут_без_лапок (Зараз в build.gradle прописано зчитування ключа саме звідти).

2. Firebase (База даних, Авторизація, Аналітика)
Для чого: Зберігання журналів користувачів (Firestore), вхід у додаток, а також збір аналітики подій і крашів (Crashlytics/Analytics).
Що потрібно від вас:
Переконатися, що у вашому Firebase-проєкті (від якого ми підключили google-services.json сьогодні) увімкнені сервіси:
Authentication (авторизація, наприклад, через Google або Email).
Firestore Database (створена база даних).
У правилах Firestore (Rules) дозволити читання/запис для авторизованих користувачів.

3. Google Play Billing API (Підписки)
Для чого: Робота Hard Paywall та стягнення $2.49/міс і $19.99/рік. У коді вже інтегрований BillingClient.
Що потрібно від вас:
Оплатити Google Play Developer Console ($25 одноразово).
Завантажити першу збірку додатку (хоча б у закрите тестування / Internal Track).
У консолі Google Play створити "Продукти за підпискою" (Subscriptions) і задати їм ідентифікатори (Product IDs), які потім потрібно прописати у коді BillingManager.kt. Без цього екран Paywall не зможе показати реальні ціни.

4. Health Connect API (Нативна синхронізація здоров'я)
Для чого: Запис калорій та макросів напряму в Android Health.
Що потрібно від вас: Ключ (API key) для цього не потрібен, оскільки це внутрішнє системне API Android. Однак Google прискіпливо ставиться до додатків, що використовують ці дані. Коли виходитимете в реліз, у маркеті треба буде заповнити "Декларацію Health Connect" і пояснити, навіщо вам доступ до даних.
5. OpenFoodFacts API (Штрих-коди)
Для чого: Альтернатива фотографіям — сканування штрих-кодів пакування (3М+ продуктів).
Що потрібно від вас: Цей сервіс безкоштовний і відкритий. Жодних API ключів чи кредиток не потрібно. У коді достатньо просто стукати на їхній REST endpoint (наприклад: https://world.openfoodfacts.org/api/v0/product/[штрихкод].json).
